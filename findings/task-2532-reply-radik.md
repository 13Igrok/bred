# Ответ Радику в задаче 2532 (черновик, НЕ отправлено)

---

Радик, спасибо за параметры, по fastPCRF всё понятно.

По IP — тут проблема: **резервных серверов пока нет.** По аудиту на площадке по одному RADIUS на домен, второго нигде нет.

Существующие подключать резервом тоже нельзя: у каждого сервера свой домен и своя база абонентов. RADIUS РТЦ абонентов РТ не авторизует. Поэтому второй экземпляр надо поднимать **в том же домене** — новый сервер + лицензия BGBilling. Как только он будет, сразу пришлём IP.

Начинать с РТ и РТЦ — ок.

Чтобы посчитать время переключения, нужно два значения:

1. `auth_resend_timeout` из `fastdpi.conf`
2. `radius_dead_timeout` — какое планируете? В примере 3600, при этом восстановившийся сервер не вернётся в Alive раньше часа. Для короткой лизы его надо меньше.

Дальше считаем по формуле:

```
время переключения ≈ response_timeout + auth_resend_timeout
лиза абонента      ≥ время переключения
```

Ещё надо сверить с BGInet:
- поддерживает ли он Status-Server (`radius_status_server=1` по умолчанию) — иначе сервер из состояния Dead не выйдет;
- CoA-порт: в конфиге 3799, а на BGInet в аудите 2001/udp.

Пришлите два значения из пунктов 1 и 2 — посчитаем время переключения и предложим лизу под РТ и РТЦ.
