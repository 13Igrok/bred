 1. АДМИНСКИЕ УЧЁТКИ  (единая модель на всех 10 хостах)
==========================================================================
Штатная группа sudo(27) ВЕЗДЕ пустая. Реальные админ-права даёт кастомная
группа omicron-sudo(gid 1001) через /etc/sudoers.d/omicron-sudo (содержимое
из-под read-only недоступно ни на одном — НЕ проверено наличие NOPASSWD).

Действующие админы (login-shell bash + omicron-sudo) — одни и те же люди:
  root
  gmasich   (g.masich@omiplat.ru)      — активен почти везде; «устаревший админ»,
                                          есть и на POWER-BI (160.46)
  rtaktarov (r.taktarov@rocketcom.ru)
  pkuzmin   (p.kuzmin@360pro.online)
  avasilev  (a.vasilev@360pro.online)  — ТОЛЬКО на bg-core (1-5), на radius НЕТ
  ansible   (сервисный)                — + группа docker

  ПРОБЛЕМЫ (общие):
  [ВЫС] Кросс-доменный админ-разброс: на каждом хосте sudo имеют учётки из ТРЁХ
        доменов (omiplat.ru, rocketcom.ru, 360pro.online). Компрометация любого
        домена => root на всей биллинг-платформе.
  [ВЫС] omicron-sudo раздут «мёртвыми душами»: 9-10 из 14-16 членов — nologin-
        учётки бывших сотрудников (aglukhov, epetrov, itronin, ishatohin,
        userobaba, akudryaeva, oborovkov, obobrovkov, vklimansky и др.). Войти
        не могут, но состоят в админ-группе — риск при восстановлении/смене shell.
  [ВЫС] ansible состоит в группе docker на ВСЕХ 10 хостах -> тривиальный privesc
        до root там, где docker.service запущен (сейчас активен только на
        bg-core-omiplat 160.54; на остальных — латентный риск).
  [СРЕД] ДУБЛЬ-ОПЕЧАТКА 'aglukhov' + 'agluchov' в omicron-sudo на трёх radius:
        160.102, 160.55, 172.16.100.27. На 110.8 и 160.88 дубля нет.
  [СРЕД] На bg-core есть отдельный /etc/sudoers.d/bitel (учётка вендора BiTel) —
        на 160.54 и др. bg-core; проверить содержимое.

  ОСОБЫЕ СЕРВИСНЫЕ SHELL-УЧЁТКИ:
  - activemq (bg-core): на 160.54 работает под своим юзером (хорошо), на 110.7 —
    исторически, java от root.
  - wildfly (996) — только на bg-core-omiplat 160.54.

  ПЛЮСЫ (везде): PermitRootLogin no, PasswordAuthentication no (только ключи);
  SUID-набор чистый; fail2ban активен.
