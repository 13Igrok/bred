## 2. Три критические находки, которых нет в вики

**КРИТ-1. Резервное копирование БД не работает.**

Подтверждено первоисточником (`audit-160.136-db-backup2.txt`):

> `[КРИТ-1]` СЕРВЕР БЭКАПОВ ПРАКТИЧЕСКИ ПУСТ. `/db-backups/{flash,omiplat,rocket,rtc,utk}/` (hour/day/month) — **0 файлов, 84K**. Диск занят лишь 2.5G из 491G (1%) — это объём ОС, дампов БД нет вообще. Бэкапы на этот сервер не поступают. Вместе с db-backup1 (там каталоги тоже пусты) → системная проблема.

Оба сервера бэкапов (`.135` и `.136`) пусты. **Расходится с вики:** страница «Логика бэкапов баз данных» описывает рабочую схему — почасовое снятие, sshfs-монтирования `/db-backups/utk`, фулбэкапы в 00:05. Схема описана, но не работает. Это объясняет, почему задача 2406 требует «выяснить состояние до обеда 30.09» — похоже, проверяли именно это.

**КРИТ-2. Анонимный Docker Registry на GitLab (`161.7`).**

> `/v2/_catalog` отдаёт репозитории без авторизации: `authsite/rocket`, `pet/api-gateway`, `pet/voice-analytics`…

Исходники и секреты в сети без пароля. В вики про это **ни слова** — есть только страница по GitLab в общих чертах.

**КРИТ-3. Открытый прокси на `sv1` (`161.12`).**

Squid 3128 + SOCKS 1080 подтверждены открытыми, **все СУБД (MySQL/PG/Redis/Mongo) и Vite dev-серверы в сети**. В вики это описано как «выход в заблокированный интернет» — служебная функция, без указания, что она доступна из сети.

## 7. Связь с вики и с моими отчётами

| Находка аудита | Есть в вики? |
|---|---|
| Бэкапы БД пусты | ❌ вики описывает схему как рабочую — **противоречие** |
| Анонимный Docker Registry | ❌ не упомянут |
| ActiveMQ CVE-2023-46604 | ❌ есть страница по диагностике, CVE не упоминается |
| `omicron-sudo` NOPASSWD ALL | ⚠️ есть в `work/ops/access`, но без факта раздутия ex-staff |
| Подрядчики с root | ❌ не упомянуто |
| Нет хостового фаервола | ⚠️ в вики есть `speedtest` как эталон, но проблема не сформулирована |
| Открытый Squid/SOCKS | ⚠️ описано как функция, без указания на сетевую доступность |

**Главное пересечение с вики** — `omicron-sudo`. Вики в `work/ops` описывает Ansible-плейбук, который блокирует (`shell → nologin`) всех, кого нет в `users.yml`. Аудит показывает, что **nologin-учётки бывших сотрудников по-прежнему состоят в `omicron-sudo` с NOPASSWD ALL** — то есть блокировка входа не равна отзыву прав. Это ровно тот вывод, что я зафиксировал в основном отчёте по разделу offboarding, теперь он подтверждён живой проверкой на 77 хостах.
